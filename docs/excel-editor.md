# 엑셀 편집기 (원본 파일 그대로 저장)

`public/excel-editor.html` — 브라우저에서 `.xlsx` / `.xlsm` 파일을 열어 표를 고치고,
**처음에 고른 바로 그 파일에 덮어써서 저장**하는 단일 페이지 도구.
저장할 때 파일을 다시 고르거나 내려받아 원본에 덮어쓰는 과정이 없다.

## 여는 방법

```sh
npm run dev
# http://localhost:4321/playground/excel-editor.html
```

배포본은 https://tjwjdl23.github.io/playground/excel-editor.html 에서 열린다.
`public/` 아래의 정적 파일이라 Astro 빌드에 그대로 복사된다.

HTML 을 `file://` 로 직접 열면 파일을 읽고 편집하는 것까지는 되지만, **원본에 저장하는
단계에서 브라우저가 쓰기 권한을 거부하는 경우가 많다.** `localhost` 로 여는 쪽을 권장한다.

## 오프라인 HTA 버전 (인터넷 · 서버 없음)

환자 정보처럼 밖으로 나가면 안 되는 자료를 다룰 때, 또는 브라우저의 `file://` 제약을
아예 피하고 싶을 때 쓴다. `hta/excel-editor.hta.html` 을 빌드하면 나오는 `.hta` 파일 하나가
전부다. 공유폴더에 두고 **더블클릭**하면 Windows 내장 `mshta.exe` 가 실행한다.

```sh
node scripts/build-standalone.mjs 엑셀편집기.hta hta/excel-editor.hta.html
```

- **네트워크를 전혀 쓰지 않는다.** 인터넷도, 로컬 서버도 필요 없다.
- 브라우저 샌드박스 밖이라 **권한 요청이 없다.** 원본 파일에 그냥 저장된다.
- 저장은 안전 순서를 지킨다: **임시 파일에 쓰기 → 다시 읽어 바이트 단위 검증 →
  원본을 `.bak` 으로 백업 → 임시 파일을 원본 자리로 이동.**
  검증에 실패하면 원본은 손대지 않고 수정 내용도 화면에 그대로 남는다.
- 파일 선택 대화상자가 전체 경로를 주지 않는 PC 를 위해, 경로를 직접 붙여넣는 칸도 있다.
  `\\10.1.5.20\공유폴더\파일.xlsx` 같은 네트워크 경로도 그대로 쓸 수 있다.

### 반드시 내 PC 에서 실행할 것

`\\서버\공유폴더\...` 에 둔 `.hta` 를 **직접 더블클릭하면 실패한다.** Windows 가 네트워크
경로를 인터넷 구역으로 취급해서, 그 구역의 HTA 는 파일에 접근할 수 없기 때문이다.
(`이 컴퓨터의 안전 설정으로는 다른 도메인의 데이터 원본에 액세스할 수 없습니다.`)

편집할 엑셀 파일은 공유폴더에 있어도 상관없다. **프로그램 파일만** 로컬 디스크에 있으면 된다.

`scripts/start-hta.bat` 을 `.hta` 와 같이 공유폴더에 두면 이 과정이 자동으로 처리된다.
`.hta` 를 `%LOCALAPPDATA%\ExcelEditor\` 로 복사한 뒤 거기서 실행한다.
`.hta` 자체도 네트워크에서 실행된 것을 감지하면 안내와 함께
[내 PC 로 복사해서 다시 열기] 버튼을 보여준다.

제약:
- IE 엔진으로 돌기 때문에 코드가 ES5 로 제한된다. 수정할 때는
  `node scripts/check-ie-compat.mjs hta/excel-editor.hta.html` 로 확인한다.
- 보안 정책으로 `mshta.exe` 나 ActiveX 가 막힌 PC 에서는 실행되지 않는다.
  그런 경우 실행 즉시 그 사실을 화면에 알린다.
- 화면 표시는 브라우저 버전보다 단순하다 (고정 헤더 없음, 밝은 테마만).

## Windows 에서 설치 없이 열기

`file://` 로 열면 편집까지는 되지만 **저장 단계에서 Chrome 이 쓰기 권한을 거부한다.**
(네트워크 공유 폴더 `\\서버\폴더\...` 에 둔 HTML 을 더블클릭한 경우가 대표적이다.)
프로토콜만 `http://127.0.0.1` 로 바꾸면 해결된다.

`scripts/serve-windows.bat` 를 편집기 HTML 과 **같은 폴더**에 두고 더블클릭하면 된다.
Python·Node 설치가 필요 없고, Windows 에 들어 있는 PowerShell 만 쓴다.

- 폴더 안의 파일을 `127.0.0.1` 로만 제공하는 최소 웹 서버를 띄우고 브라우저를 연다.
- 포트는 8123 부터 비어 있는 것을 고른다.
- 검은 창을 닫으면 서버도 끝난다.

네트워크 드라이브에서 `.bat` 실행이 막혀 있으면 **HTML 과 `.bat` 을 로컬 폴더
(예: 바탕화면)로 복사한 뒤** 실행한다. 편집할 엑셀 파일은 네트워크 드라이브에 그대로 두어도 된다.

Python 이 있다면 `.bat` 대신 이것도 된다:

```sh
python -m http.server 8000
# http://localhost:8000/엑셀편집기.html
```

## 사용 순서

1. **[엑셀 파일 열기]** → 파일을 하나 고른다.
2. 셀을 클릭해 값을 고친다. 바뀐 셀은 노란색으로 표시된다.
3. **[저장]** (또는 `Ctrl`/`Cmd` + `S`) → 1번에서 고른 파일에 바로 덮어써진다.

| 조작 | 동작 |
| --- | --- |
| `Enter` / `↓` / `↑` | 위아래 셀로 이동 |
| `Esc` | 그 셀의 수정 취소 |
| `=` 로 시작 | 수식으로 저장 (`=B2*C2`) |
| 빈 값으로 저장 | 셀 비우기 |
| [변경 취소] | 저장하지 않은 수정 전체 되돌리기 |

## 입력값 해석 규칙

| 입력 | 저장되는 형태 |
| --- | --- |
| `123`, `-4.5`, `1.5e3` | 숫자 |
| `0123`, `010-1234-5678` | 문자열 (앞의 `0` 이 보존된다) |
| `=SUM(A1:A9)` | 수식. 결과값은 Excel 이 파일을 열 때 계산한다 |
| `2026-03-01` | 원래 **날짜 서식** 셀이면 날짜, 아니면 문자열 |
| (빈 값) | 빈 셀 |

## 왜 서식이 안 깨지나

`.xlsx` 는 XML 여러 개가 들어있는 zip 파일이다. 보통의 라이브러리는 워크북을
읽어서 **처음부터 다시 쓰기** 때문에, 그 라이브러리가 모르는 요소(차트, 조건부 서식,
매크로, 시트 보호 등)는 저장하는 순간 사라진다.

`public/vendor/xlsx-core.js` 는 그렇게 하지 않는다. zip 을 풀어서 **편집한 셀이 들어있는
시트 XML 만** 고치고, 나머지 엔트리는 원본 바이트 그대로 다시 압축한다. 그래서

- 셀 서식 · 조건부 서식 · 차트 · 이미지 · 매크로 · 시트 보호 → 그대로 유지
- 건드리지 않은 시트의 XML → 바이트 단위로 동일
- 편집하지 않은 수식과 그 캐시 결과값 → 그대로 유지

셀을 고치면 다른 수식의 캐시 결과값이 낡게 되므로, 저장할 때
`calcChain.xml` 을 지우고 워크북에 `fullCalcOnLoad` 플래그를 세운다.
Excel 이 파일을 열면서 수식을 다시 계산한다.

## 브라우저 지원

원본 파일 덮어쓰기는 [File System Access API](https://developer.mozilla.org/docs/Web/API/File_System_Access_API)
를 쓴다. 데스크톱 **Chrome · Edge · Opera** 에서 동작한다.
지원하지 않는 브라우저(Firefox, Safari)에서는 페이지 상단에 안내가 뜨고,
[저장]이 **수정본 내려받기**로 대체된다.

파일은 브라우저 안에서만 처리되며 서버로 전송되지 않는다.

## 저장이 안 될 때

브라우저는 파일 쓰기 권한을 **최상위 창에서, 사용자가 버튼을 누른 직후에만** 내준다.
이 조건이 깨지면 `Not allowed to request permissions in this context` 같은 오류가 난다.

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 저장 시 권한 오류 | 페이지가 **iframe · 미리보기 창** 안에 있다 | 새 탭에서 HTML 을 직접 연다 (페이지 상단에 경고가 뜬다) |
| 저장 시 권한 오류 (`Not allowed to request permissions in this context`) | **`file://` 로 열었다** — Chrome 은 이 주소에 파일 쓰기 권한을 주지 않는다 | `scripts/serve-windows.bat` 로 열거나 `python -m http.server` 를 쓴다 (위 참고) |
| 저장 시 권한 오류 | 엑셀 파일이 **브라우저가 보호하는 폴더**(사용자 홈 최상위, Program Files, 일부 동기화 폴더)에 있다 | 파일을 문서·바탕화면 등 일반 폴더로 옮긴다 |
| "파일이 다른 프로그램에서 열려 있습니다" | Excel 이 그 파일을 잠그고 있다 | Excel 에서 파일을 닫고 다시 저장 |
| 저장 버튼이 눌리지 않음 | 수정한 셀이 없다 | 셀을 고치면 활성화된다 |

어떤 경우든 **수정 내용은 사라지지 않는다.** 저장에 실패하면 상단에
**[위치를 골라 저장…]** 과 **[수정본 내려받기]** 버튼이 나타난다.
[위치를 골라 저장…] 에서 원래 파일을 다시 고르면 그 파일에 덮어써지고,
그 뒤로는 [저장]만 눌러도 대화상자 없이 바로 저장된다.

페이지 하단(또는 저장 실패 시 자동으로) 열리는 **환경 진단** 패널에 주소·프로토콜·
최상위 창 여부·API 지원 여부·마지막 오류가 정리돼 있다. 원인을 좁힐 때 이걸 보면 된다.

압축(직렬화)은 쓰기 스트림을 연 **뒤에** 한다. 순서를 반대로 하면 큰 파일에서
압축하는 동안 사용자 조작의 유효 시간이 지나 권한 요청이 거부된다.
`tests/excel-editor/ui.test.mjs` 의 `[UI-7]` 이 이 순서를 지킨다.

## 알려진 한계

- 값 편집 전용이다. 서식 변경, 행·열 삽입/삭제, 셀 병합은 지원하지 않는다.
- 화면에는 셀의 **값**만 표시된다. 글꼴·색·표시 형식은 보이지 않지만 파일에는 그대로 남는다.
- 숫자 표시 형식(통화, 소수 자릿수 등)은 적용되지 않은 원본 숫자로 보인다. 날짜만 예외로 `YYYY-MM-DD` 로 보여준다.
- 수식 셀을 편집하면 그 셀의 수식은 사라지고 입력한 값이 들어간다 (Excel 과 같은 동작).
- 큰 시트는 300행씩 나눠서 그린다. 아래쪽 [행 더 보기] 버튼으로 이어서 볼 수 있다.
- 구형 `.xls`(바이너리) 는 열 수 없다. Excel 에서 `.xlsx` 로 저장한 뒤 사용한다.
